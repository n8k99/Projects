# G031 -- CD Key Generator

> Self-verifying tokens: the key carries its own proof.

## Constants

```innate
(def +charset+ "ABCDEFGHIJKLMNOPQRSTUVWXYZ0123456789")
(def +group-len+ 5)
(def +data-groups+ 4)
(def +prime+ 65521)
```

## Checksum

The checksum is a **one-way function** embedded in the key itself. The issuer computes it; the validator recomputes it. No database. No callback. The key *is* the proof.

```innate
(defn compute-checksum [groups]
  "Derive 5-char checksum from the data groups."
  (let [raw   (apply str groups)
        bytes (map char-code raw)
        h     (mod (reduce + (map-indexed (fn [i b] (* b (inc i))) bytes))
                   +prime+)]
    (loop [h h, i 0, acc []]
      (if (= i +group-len+)
        (apply str acc)
        (recur (quot h (count +charset+))
               (inc i)
               (conj acc (nth +charset+ (mod h (count +charset+)))))))))
```

## Generate

Each key is independently nondeterministic -- 4 random groups plus one deterministic checksum derived from them.

```innate
(defn random-group []
  (apply str (repeatedly +group-len+ #(rand-nth +charset+))))

(defn generate-key []
  "Generate a CD key: XXXXX-XXXXX-XXXXX-XXXXX-XXXXX"
  (let [groups (repeatedly +data-groups+ random-group)
        check  (compute-checksum groups)]
    (str/join "-" (conj (vec groups) check))))
```

## Validate

Offline verification: recompute the checksum from the first 4 groups and compare against the 5th. The validator needs no external state.

```innate
(defn validate-key [key]
  "Validate a CD key by recomputing its checksum."
  (let [parts (str/split (str/upper-case (str/trim key)) #"-")]
    (and (= (count parts) (inc +data-groups+))
         (every? #(= (count %) +group-len+) parts)
         (every? #(every? (set +charset+) %) parts)
         (= (nth parts +data-groups+)
            (compute-checksum (take +data-groups+ parts))))))
```

## Batch Generation

Batch generation is `@map` over nondeterminism -- apply a nondeterministic function n times independently.

```innate
(defn generate-batch [n]
  "@map generate-key over n independent trials."
  (repeatedly n generate-key))
```

## Insights

### Self-Verifying Tokens

A CD key is a **TOKEN** -- a compact string that encodes both randomness (the first 4 groups) and verification (the checksum group). This is the first self-verifying artifact in the Rosetta Stone. Unlike G013's credit card (where Luhn checks structural validity), the CD key's checksum is GENERATED by the issuer and VERIFIED by the consumer without communication. The key carries its own proof.

### Offline Verification

Self-verifying tokens are **OFFLINE VERIFICATION** -- no database lookup needed. The validator recomputes the checksum from the key itself. This is the opposite of G012's fact lookup (which requires external state). Self-contained verification scales infinitely because each validation is independent. In InnateScript, this maps to agent credentials: a token that proves an agent's authorization without calling back to a central authority.

### One-Way Functions

The checksum is a **ONE-WAY FUNCTION** applied to the key's data -- easy to compute, embedded in the key, verifiable by anyone. This is a simplified version of digital signatures. The issuer "signs" the key by computing the checksum. The validator "verifies" by recomputing. The security is weak (reversible), but the pattern is real.

### Batch as @map over Nondeterminism

Batch generation (`generate_batch`) is `@map` over nondeterminism -- generate n independent keys. Each key is independently random. This is G017's `@map` + G024's nondeterminism combined: apply a nondeterministic function n times independently.

### Choreographic Pattern: License Management

An agent issues keys to users. Another agent validates keys at runtime. The issuing and validating agents don't need to communicate -- the key *is* the communication. Self-verifying tokens decouple issuance from validation. The token becomes a message that carries its own authentication.
